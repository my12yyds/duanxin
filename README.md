# 用户短信安全协议（USS-P）

**先体验：** [打开在线工作台](https://my12yyds.github.io/duanxin/) · [阅读协议草案](SPEC.md) · [提交建议或问题](https://github.com/my12yyds/duanxin/issues/new/choose)

**USS-P（User SMS Safety Protocol）** 是一份面向应用、通知服务和短信网关的早期开放协议草案，并附有中文用户防诈指南、机器可读 JSON Schema、测试样例和本地参考工作台。目标是让“谁因为什么、基于什么依据、在什么限制下请求发送短信”变得明确、可检查、可撤回、可审计。

> **项目状态：草案 0.1.0，尚未成为正式标准。** 它不是运营商短信传输协议，不能认证普通短信显示的发件人名称，也不能单独证明某项同意或业务关系真实有效。仓库没有真实短信发送接口。请只使用虚构资料。

## 为什么做这个项目

短信仍广泛用于服务通知、账户安全和用户主动发起的一次性验证，但应用层对用途、同意、退订、时效、频率、幂等及隐私审计的处理通常各不相同。USS-P 希望先把这些最低安全上下文整理为公开、可讨论、可机器检查的配置文件，并通过示例暴露其边界和失败情况。

目前项目处于早期阶段，没有可报告的星标、下载量或外部互操作采用数据。我们会在有真实公开证据后再更新使用情况，不以估算或演示访问代替采用指标。

## 1 分钟体验

打开[在线参考工作台](https://my12yyds.github.io/duanxin/)，进入“活动演练”并创建一次本地演练，即可查看授权、退订抑制和频率规则如何影响资格结果。整个演示只使用虚构资料，不会连接短信服务商或发送消息。无需安装即可体验；想在本机运行校验器，再按下面步骤操作。

## 快速开始

参考校验器需要 Node.js 22 或更新版本。前端工作台本身不需要构建；开发校验器使用 Ajv 检查 JSON Schema：

```sh
npm ci
npm test
npm run validate:examples
```

命令会运行协议验证器测试，并检查本仓库的有效/无效示例。自动检查也会在 Pull Request 和推送到 `main` 时运行。通过 Schema 不能证明同意或业务事件真实，也不能代替服务端授权、抑制和安全评审。

本地打开 `public/index.html` 可体验参考工作台；也可用静态文件服务器托管 `public/`。联系人和操作数据保存在当前浏览器的 `localStorage` 中。不要输入真实号码、客户资料、验证码、令牌或生产数据。

## 协议要点

- 一条发送意图只能声明一种用途类别：`service`、`security`、`otp` 或 `marketing`。
- 营销消息要求针对该渠道与用途的明确同意，并且必须提供退订说明。
- OTP 必须响应用户主动发起的短时挑战，不带链接或营销内容，实施方还需限制尝试并避免记录口令。
- 网关必须在实际投递前再次检查退订、授权、频率、静默时段、过期和幂等状态；退订优先于待发送队列。
- 发送身份通过应用到网关的认证建立；SMS 显示名称本身不是身份凭证。
- 审计使用最少必要的引用和结果代码，不记录完整号码或短信/OTP 正文。

详细要求及限制见 [SPEC.md](SPEC.md)。
